GET /api/appointments

Obtiene la lista de citas del paciente autenticado con paginación y filtros opcionales.

Headers Requeridos

Authorization: Bearer {token}

Parámetros de Consulta (Query Parameters)

Parámetro Tipo Requerido Descripción
page integer No Número de página (por defecto: 1)
per_page integer No Elementos por página (1-100, por defecto: 10)
status string No Filtrar por estado: proposed, booked, checked-in , arrived, fulfilled , cancelled , noshow, entered-in-error
date_from date No Fecha desde (YYYY-MM-DD)
date_to date No Fecha hasta (YYYY-MM-DD)

Ejemplo de Petición

GET /api/appointments?page=1&per_page=5&status=booked&date_from=2025-09-01 Authorization: Bearer 1|abcd1234...

Respuestas

200 Lista de citas obtenida exitosamente
{ "data": [ { "id": 1, "status": "booked", "description": "Consulta general", "start": "2024-02-15 10:00:00", "end": "2024-02-15 10:30:00", "formatted_date": "15 de febrero, 2024", "formatted_time": "10:00 AM - 10:30 AM", "minutes_duration": 30, "practitioner": { "id": 1, "name": "Dr. Juan Pérez", "speciality": "Medicina Interna" }, "consulting_room": { "id": 1, "name": "Consultorio 101" }, "can_cancel": true, "can_reschedule": true } ], "pagination": { "current_page": 1, "per_page": 5, "total": 25, "last_page": 5, "from": 1, "to": 5, "has_more_pages": true } }
401 Usuario no autenticado
{ "message": "Usuario no autenticado" }

{ "message": "Paciente no encontrado" }
POST /api/appointments

Crea una nueva cita médica para el paciente autenticado.

Headers Requeridos

Authorization: Bearer {token} Content-Type: application/json

Parámetros de Entrada

Campo Tipo Requerido Descripción
patient_id integer Sí ID del paciente
practitioner_id integer Sí ID del médico
medical_speciality_id integer Sí ID de la especialidad
start datetime Sí Fecha y hora de inicio (YYYY-MM-DD HH:mm:ss)
minutes_duration integer SI Duración en minutos (por defecto: 30)
service_type string SI Tipo de cita
consulting_room_id integer No ID del consultorio
description string No Descripción de la cita

Ejemplo de Petición

POST /api/appointments Authorization: Bearer 1|abcd1234... Content-Type: application/json { "patient_id": 1, "practitioner_id": 1, "medical_speciality_id": 32, "consulting_room_id": 1, "start": "2024-02-15 10:00:00", "minutes_duration": 30, "description": "Consulta general", "service_type": "Revisión médica anual" }

Respuestas

201 Cita creada exitosamente
{ "message": "Cita creada exitosamente", "appointment": { "id": 2, "status": "booked", "description": "Consulta general", "start": "2024-02-15 10:00:00", "end": "2024-02-15 10:30:00", "practitioner": { "id": 1, "name": "Dr. Juan Pérez" }, "consulting_room": { "id": 1, "name": "Consultorio 101" } } }
422 Error de validación
{ "message": "Los datos proporcionados no son válidos.", "errors": { "practitioner_id": ["El médico seleccionado es requerido"], "start": ["La fecha de inicio debe ser futura"] } }

PUT /api/appointments/{id}

Actualiza una cita existente (reprogramación).

Importante: Solo se pueden actualizar citas que estén en estado 'booked' y que no hayan pasado su fecha límite de cancelación.

Headers Requeridos

Authorization: Bearer {token} Content-Type: application/json

Parámetros de Entrada

Campo Tipo Requerido Descripción
start datetime No Nueva fecha y hora de inicio
duration integer No Nueva duración en minutos
description string No Nueva descripción

Respuestas

200 Cita actualizada exitosamente
{ "message": "Cita actualizada exitosamente", "appointment": { "id": 1, "status": "booked", "start": "2024-02-16 14:00:00", "end": "2024-02-16 14:30:00" } }
DELETE /api/appointments/{id}

Cancela una cita médica.

Headers Requeridos

Authorization: Bearer {token}

Respuestas

200 Cita cancelada exitosamente
{ "message": "Cita cancelada exitosamente" }

{ "message": "No se puede cancelar esta cita" }

Parámetros de Consulta

API v1 - Integración Externa

Autenticación API v1: Estos endpoints requieren un token API válido con los scopes apropiados.
Authorization: Bearer {api-token}
GET /api/v1/appointments

Lista todas las citas del sistema con filtros avanzados y paginación. Diseñado para integraciones externas.

Headers Requeridos

Authorization: Bearer {api-token} Accept: application/json

Parámetros de Consulta

Parámetro Tipo Requerido Descripción
page integer No Número de página (por defecto: 1)
per_page integer No Elementos por página (1-100, por defecto: 15)
search string No Buscar por paciente, médico o descripción
status string No Filtrar por estado: requested, confirmed, booked, arrived, fulfilled, cancelled, no_show
patient_id integer No Filtrar por ID del paciente
practitioner_id integer No Filtrar por ID del médico
medical_speciality_id integer No Filtrar por especialidad médica
date_from date No Fecha de inicio del filtro (YYYY-MM-DD)
date_to date No Fecha de fin del filtro (YYYY-MM-DD)
order_by string No Ordenar por: start, end, created_at, updated_at, status
order_direction string No Dirección: asc, desc (por defecto: desc)

PUT /api/v1/appointments/{id}

Actualiza una cita existente. Solo se actualizan los campos proporcionados.

Headers Requeridos

Authorization: Bearer {api-token} Accept: application/json Content-Type: application/json

Parámetros del Cuerpo (Opcionales)

Parámetro Tipo Descripción
patient_id integer ID del paciente
practitioner_id integer ID del médico
start datetime Fecha y hora de inicio
minutes_duration integer Duración en minutos (15-480)
status string Estado: requested, confirmed, booked, arrived, fulfilled, cancelled, no_show
description string Descripción
medical_speciality_id integer ID de la especialidad médica
consulting_room_id integer ID del consultorio

PUT /api/v1/appointments/1 Authorization: Bearer mdt_abc123... Accept: application/json Content-Type: application/json { "status": "confirmed", "description": "Consulta de seguimiento - confirmada" }

Respuesta Exitosa (200)

{ "message": "Cita actualizada exitosamente", "data": { // Datos de la cita actualizada (mismo formato que show) } }

Características de la API v1 para Citas

  • Acceso Completo: Las integraciones externas pueden gestionar citas de todos los pacientes
  • Filtros Avanzados: Múltiples opciones de filtrado por fecha, estado, médico, etc.
  • Validación de Conflictos: Verificación automática de disponibilidad antes de crear/actualizar
  • Estados de Cita: Soporte completo para todo el flujo de estados de citas médicas
  • Notificaciones: Las citas creadas vía API v1 envían notificaciones automáticamente
  • Integración FHIR: Todos los datos siguen estándares FHIR para interoperabilidad
