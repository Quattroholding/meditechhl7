Arquitectura SAMI

Sistema Integral de Gestión Sanitaria - Multi-Tenant Healthcare Platform

Versión: Laravel 13 | PHP 8.3 | React 18 | Livewire 4 | MySQL | Laravel Octane

1
Introducción General

SAMI es una plataforma integral de gestión sanitaria basada en arquitectura de microservicios e integraciones externas. El sistema proporciona soluciones completas para clínicas, hospitales y consultorios médicos con capacidades de:

  • Gestión multi-tenant con aislamiento de datos por cliente
  • Historias clínicas electrónicas (EHR) basadas en estándares FHIR
  • Programación de citas con calendario interactivo
  • Videollamadas integradas con Zoom
  • Sincronización con calendario de Microsoft
  • Notificaciones por WhatsApp y SMS (Twilio)
  • Almacenamiento en la nube (AWS S3, Dropbox)
  • Comunicación en tiempo real (Pusher + Laravel Echo)
  • Control de acceso basado en roles (RBAC)
  • Auditoría completa de operaciones (BaseModel logging)

Flujo de Autenticación OAuth con Zoom

El flujo OAuth 2.0 permite que los médicos conecten sus cuentas de Zoom sin compartir contraseñas directamente.

1
Usuario Inicia Conexión
El médico hace clic en "Conectar con Zoom" en las configuraciones del perfil.
↓
2
Redirección a OAuth Authorization Endpoint
ZoomOAuthController::authorize() construye URL hacia:
https://zoom.us/oauth/authorize?response_type=code&client_id=...&redirect_uri=...&scope=meeting:write:meeting user:read:user&state=...
↓
3
Usuario Autoriza en Zoom
El usuario inicia sesión en zoom.us y autoriza permisos. Zoom valida las credenciales.
↓
4
Callback con Authorization Code
Zoom redirige a route('zoom.callback') con parámetros:
?code=AUTHORIZATION_CODE&state=SESSION_STATE
↓
5
Intercambio de Código por Access Token (Backend)
El servidor intercambia el código por tokens mediante POST a:
https://zoom.us/oauth/token
Con credenciales: client_id:client_secret (Basic Auth) + grant_type=authorization_code
↓
6
Recepción de Tokens
Zoom responde con: access_token, refresh_token, expires_in (3600s)
↓
7
Obtención de Perfil del Usuario
GET request a https://zoom.us/v2/users/me con el access_token para obtener datos del usuario.
↓
8
Almacenamiento en Base de Datos
PractitionerZoomProfile::updateOrCreate() guarda:
✓ zoom_user_id | zoom_email | access_token | refresh_token | token_expires_at | verified_at
↓
9
Confirmación al Usuario
Redirección a route('practitioner.settings.zoom') con mensaje de éxito.
Tokens y Seguridad
  • Access Token: Válido por 3600 segundos (1 hora) - usado para llamadas API
  • Refresh Token: Válido por 15 días - permite renovar access token sin re-autorizar
  • State Parameter: CSRF protection usando session()->token()
  • Almacenamiento: Los tokens se encriptan en la DB (Laravel encryption)
  • Logging: Toda la operación se registra en logs de aplicación para auditoría
Consideración Importante: Zoom puede enviar solicitudes de validación de webhook a cualquier URL registrada (incluyendo el callback OAuth). El código detecta estas solicitudes por el parámetro event=endpoint.url_validation y responde con el token encriptado HMAC-SHA256.

Sistema de Webhooks de Zoom

Los webhooks permiten que Zoom notifique a SAMI sobre eventos en tiempo real. 

ZOOM WEBHOOK FLOW
═════════════════════════════════════════════════════════════════════════════

Registro de Webhook (Manual en Zoom App Marketplace):
┌─────────────────────────────────────────────────────────────────┐
│ URL: https://SAMI.com/api/webhooks/zoom                   │
│ Secret: [configurado en config/services.php]                   │
│ Eventos Suscritos:                                              │
│  ├─ meeting.started       (Reunión iniciada)                   │
│  ├─ meeting.ended         (Reunión finalizada)                 │
│  ├─ meeting.participant_joined    (Participante se une)        │
│  ├─ meeting.participant_left      (Participante se va)         │
│  ├─ recording.started     (Grabación iniciada)                 │
│  ├─ recording.completed   (Grabación completada)               │
│  └─ recording.deleted     (Grabación eliminada)                │
└─────────────────────────────────────────────────────────────────┘

Validación del Webhook:
┌─────────────────────────────────────────────────────────────────┐
│ 1. Zoom envía POST con headers:                                │
│    - x-zm-request-timestamp: [Unix timestamp]                  │
│    - x-zm-signature: v0=[HMAC-SHA256]                          │
│                                                                 │
│ 2. SAMI verifica:                                         │
│    ├─ Token generado = HMAC-SHA256(                            │
│    │   webhook_secret,                                         │
│    │   timestamp + request_body                                │
│    │ )                                                          │
│    └─ Valida que x-zm-signature coincida                       │
│                                                                 │
│ 3. Detecta endpoint.url_validation:                            │
│    └─ Responde con plainToken + encryptedToken               │
└─────────────────────────────────────────────────────────────────┘

Procesamiento de Eventos:
┌─────────────────────────────────────────────────────────────────┐
│ EVENTO: meeting.started                                        │
│ ├─ Datos: meeting_id, user_id, operator_id, duration          │
│ └─ Acción: Actualizar estado de Appointment a "IN_PROGRESS"   │
│                                                                 │
│ EVENTO: meeting.ended                                          │
│ ├─ Datos: meeting_id, user_id, end_time, duration             │
│ └─ Acciones:                                                   │
│    ├─ Marcar Appointment como completada                       │
│    ├─ Registrar duración real de consulta                      │
│    └─ Disparar evento: ConsultationCompleted                  │
│                                                                 │
│ EVENTO: meeting.participant_joined / participant_left         │
│ ├─ Datos: meeting_id, participant (id, email, name)          │
│ └─ Acción: Registrar participantes en auditoría                │
│                                                                 │
│ EVENTO: recording.completed                                   │
│ ├─ Datos: meeting_id, recording_files[], download_url        │
│ └─ Acciones:                                                   │
│    ├─ Descargar grabación a AWS S3                            │
│    ├─ Vincular grabación a Appointment                        │
│    └─ Enviar notificación al médico                           │
└─────────────────────────────────────────────────────────────────┘

Database Storage:
┌─────────────────────────────────────────────────────────────────┐
│ Table: zoom_webhooks                                           │
│ ├─ id                                                          │
│ ├─ event_type (meeting.started | meeting.ended | ...)         │
│ ├─ zoom_meeting_id                                            │
│ ├─ event_payload (JSON)                                       │
│ ├─ processed_at                                                │
│ ├─ created_at / updated_at                                    │
│ └─ Notes: Guardar webhook para debugging/replay               │
│                                                                 │
│ Table: appointments                                            │
│ ├─ zoom_meeting_id (vinculación)                              │
│ ├─ zoom_start_at / zoom_end_at                               │
│ ├─ zoom_duration_minutes                                      │
│ ├─ zoom_recording_url                                         │
│ ├─ status (SCHEDULED, IN_PROGRESS, COMPLETED, CANCELLED)     │
│ └─ metadata (JSON: participant_ids, recording_ids)            │
└─────────────────────────────────────────────────────────────────┘
Seguridad de Webhooks:
  • Validar firma HMAC-SHA256 antes de procesar cualquier webhook
  • Rechazar webhooks antiguos (verificar timestamp dentro de 5 minutos)
  • No confiar en datos no validados del webhook payload
  • Guardar todos los webhooks en DB para auditoría y replay si es necesario
  • Implementar idempotencia: mismo webhook no debe procesarse 2 veces

Seguridad y Compliance
Estándares de Cumplimiento:
  • HIPAA (USA): Ley de Portabilidad y Responsabilidad de Seguros de Salud
  • GDPR (EU): Reglamento General de Protección de Datos
  • FHIR: Fast Healthcare Interoperability Resources - Estándar OHF
  • ISO/IEC 27001: Seguridad de la información
Medidas de Seguridad Implementadas:
  • Autenticación: Laravel Fortify + Email verification + Passkeys
  • Autorización: Spatie Permission con roles (admin, doctor, paciente, asistente)
  • Encriptación: Tokens OAuth encriptados en DB usando Laravel encryption
  • CSRF Protection: State parameter en OAuth, token CSRF en formularios
  • HMAC Validation: Webhooks de Zoom validados con SHA256
  • Isolation Multitenant: Global Scopes filtra automáticamente por Client
  • Rate Limiting: Throttle en rutas públicas (login, reset password)
  • Logging Completo: Auditoría de TODAS las operaciones CRUD
  • SSL/TLS: HTTPS obligatorio en producción
  • SQL Injection Prevention: Eloquent ORM con prepared statements
  • XSS Protection: Blade templates con escaping automático
Flujo de Datos Sensibles
Paciente → Médico (Consulta):
Datos clínicos encriptados en tránsito (HTTPS) y en reposo (DB encryption). Acceso restringido por Role-Based Access Control (RBAC). Auditoría completa de quién accedió qué y cuándo.

Tokens OAuth (Zoom/Microsoft):
Almacenados encriptados en tabla practitioner_zoom_profiles. No expuestos en logs o errores públicos. Refresh automático antes de expiración.

Grabaciones de Zoom:
Descargadas directamente de Zoom a AWS S3 (sin pasar por servidor local). Almacenadas con versioning y respaldo automático. Acceso solo mediante presigned URLs de corta duración (24h).

Conclusión

SAMI es una arquitectura enterprise-grade diseñada para gestión integral de sanitarios. Su fortaleza radica en:
